# M1.5 bounded pilot — sanitized mechanics gap report

A bounded private owned-source pilot was executed locally against the merged M1.4 boundary
(`main` @ `dc3d004`) to test whether the schema-v2 importer and rules engine can represent and
execute a real martial character path from level 1 to level 5.

No private, licensed or official content is referenced here: no titles, names, page numbers,
source text or private identifiers. Every gap below is reproduced with original synthetic
content in [`tests/m1.5-gap-reproductions.test.ts`](../tests/m1.5-gap-reproductions.test.ts).

## What held

The import boundary behaved exactly as M1.4 documents. Schema validation, cross-file reference
resolution, conflict checks and confirmation all passed, confirmation used **one** flat Dexie
transaction, and re-importing the same version was correctly blocked. Level-keyed progression,
per-level scaling, critical-range modification, minimum-value effects, species speed as a base
value, background-to-feat activation and proficiency grants all executed correctly.

The pilot did **not** reach a verified character derivation. Import success is not mechanical
success, and this report exists because the two diverged.

## Gaps

| ID | Capability | Category | Severity | Affected module |
| --- | --- | --- | --- | --- |
| G-1 | Option grants never activate the entry they name | Rules-engine execution gap | High | `src/rules/derive-character.ts` (`src/rules/engine.ts` for the trace) |
| G-2 | A resource cannot declare two rest cadences or a partial recovery amount | Schema-expression gap | High | `src/domain/model.ts`, `src/domain/content-pack.ts`, `src/rules/engine.ts` |
| G-3 | A resource maximum has three representations and no canonical source | Schema-expression gap | Medium | `src/domain/model.ts`, `src/rules/derive-character.ts` |
| G-4 | One unresolved choice emits two diagnostics | Derived-character gap | Low | `src/rules/choice-resolution.ts` |
| G-5 | Declared origin ability-score increases are unresolvable | Derived-character gap | Medium | `src/domain/content-pack.ts`, `src/rules/derive-character.ts` |

### G-1 — option grants are inert

`grantFightingStyle`, `addWeaponMastery`, `grantManeuver`, `grantInvocation` and `grantMetamagic`
record an option ID in `RuleResult.optionGrants` and trace as `applied: true`. Nothing then
resolves that ID to a content entry, so the named entry is never activated and its own effects
never execute. Derivation reports `ready` with no issue.

This is the silent-no-op class that M1.4 set out to eliminate. The effect is not ignored — it is
traced — but it produces no mechanical consequence, and content authored against it is dead.
An entry reached through a choice option `entryId` activates correctly, which is the contrast
the reproduction pins.

**Proposed contract change:** either resolve option-grant IDs to entries and activate them the
way choice targets are activated, or emit a typed issue when an option grant names an ID that is
never resolved. Silence in both directions is the defect.

### G-2 — resource recharge cannot express partial or dual cadence

`ResourceDefinition.recharge` is a single enum, and `rechargeOnShortRest` / `rechargeOnLongRest`
write one value per resource ID into `RuleResult.resourceRecharge`. Applying both silently keeps
the last one. A resource that recovers *some* uses on a short rest and *all* on a long rest —
an extremely common martial pattern — cannot be expressed at all.

**Proposed contract change:** model recovery as a set of `{ cadence, amount }` rules rather than
one cadence per resource, where amount can be a fixed count or "all".

### G-3 — no canonical resource maximum

Three independent mechanisms can each set a maximum for one resource: `ResourceDefinition.maximum`,
class progression `resourceChanges`, and a `scaleAtLevel` effect writing a free-form value key.
They can disagree simultaneously, with no declared precedence and no diagnostic. The reproduction
produces three different numbers for one resource in a `ready` derivation.

**Proposed contract change:** declare one canonical source, derive the others from it, and report
a typed issue when a second mechanism contradicts the canonical value.

### G-4 — duplicate unresolved-choice diagnostics

A required choice with no selection produces both `CHOICE_REQUIRED` and `CHOICE_COUNT_INVALID`
for the same choice ID, so a consuming surface shows one missing decision twice.

**Proposed contract change:** emit one diagnostic per unresolved choice.

### G-5 — declared origin ability increases are unresolvable

Background mechanics declare an ability-score increase spread, but nothing consumes it: no
abilities change, no choice becomes pending, and derivation reports `ready`. The declaration is
also shaped as a single pattern array, so an origin offering an either/or spread cannot be
represented.

**Proposed contract change:** express the increase as a resolvable choice with alternative
patterns, and apply the selection inside the derivation boundary.

## Scope note

Armour class, hit points and attack/save expressions are absent from derivation by design — M1.4
assigns them to the M2.1 automatic-sheet contract. They are listed here only so their absence is
not mistaken for a gap.

Spellcasting, multiclassing and creature dependencies were out of scope for this pilot and remain
so; they need their own bounded pilots.

## Status

No production code was changed. The reproductions are characterization tests that pin current
behaviour so it cannot drift, each stating the behaviour a future approved fix should establish.
Fixing G-1, G-2, G-3 and G-5 touches files that the concurrent M2.1 work also consumes, so the
fix needs sequencing against that branch rather than landing opportunistically.
