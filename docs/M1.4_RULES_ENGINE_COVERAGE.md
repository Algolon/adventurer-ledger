# M1.4 rules-engine coverage

## Outcome

M1.4 closes the silent-effect, dice/roll, equipment-bundle, and baseline multiclass gaps with additive schema-v2 fields. It does not convert or include private content. Existing schema-v2 documents remain valid: new entry collections default to empty, new progression collections default to empty, and new effect variants are opt-in.

## Effect capability matrix

The machine-readable source of truth is `src/rules/effect-capabilities.ts`. TypeScript requires every member of `Effect["type"]` to occur in that map, and the engine uses an exhaustive switch. Golden tests require every mapped variant to produce an explicit runtime trace.

| Schema support | Runtime disposition | Effect variants |
| --- | --- | --- |
| supported | automatic | `grantProficiency`, `grantExpertise`, `grantFeature`, `replaceFeature`, `disableFeature`, `modifyAbility`, `modifyAbilityMaximum`, `modifySkill`, `modifySavingThrow`, `modifyArmorClass`, `modifyInitiative`, `modifySpeed`, `modifyCriticalRange`, `modifyAttack`, `modifyDamage`, `addSpell`, `addSpellList`, `addResource`, `addAttack`, `addAction`, `addBonusAction`, `addReaction`, `setMinimum`, `setMaximum`, `setCalculation`, `addAdvantage`, `addDisadvantage`, `rechargeOnShortRest`, `rechargeOnLongRest`, `unlockAtLevel`, `scaleAtLevel`, `addWeaponMastery`, `grantFightingStyle`, `grantManeuver`, `grantInvocation`, `grantMetamagic`, `addDice`, `replaceDice`, `rerollDice`, `setMinimumRoll`, `grantEquipmentBundle` |
| supported | choice-driven | `grantChoice` |
| supported | manual-adjudication / review-required | `manualAdjudication` |

There are 43 allowed variants: 41 automatic, one choice-driven, and one explicitly manual. A condition or level gate that does not match is traced as such. Choice-driven and manual effects create visible structured issues. Evaluation failure is an error. No valid effect can fall through as “applied” without a handler.

## Dice and rolls

The runtime records extra dice, dice replacement, bounded rerolls, minimum rolls, critical-range changes, advantage/disadvantage, and conditional modifiers as structured derived state. It does not roll dice. Targets and selectors remain declarative identifiers; consumers decide when a registered rule applies.

## Equipment bundles

Entries may define first-class bundles containing fixed items, nested bundles, nested choices, quantities, alternatives, and `granted`, `carried`, or `equipped` status. Backgrounds opt in through the new `equipmentBundleIds`; the existing `equipmentChoiceIds` keeps its previous aggregate-entry meaning. Bundle resolution is pure and deterministic. Import-set preview blocks missing bundle and item references, including broken alternatives. Currency alternatives are represented but remain a choice for the builder rather than being silently selected.

## Multiclass semantics

Class progression levels are class levels. `Character.level` is total level. Class mechanics can declare starting proficiencies, multiclass prerequisites, multiclass-only proficiency grants, spell-slot progression (`none`, `full`, `half`, `third`, or `pact`), explicit up/down contribution rounding, and unsupported class combinations. Subclass and progression choices are gated by class level. Combined full/half/third caster slots use the standard level table; pact slots stay separate and produce `review-required` when combined with other spellcasting.

Unsupported or inconsistent states are machine-readable: level-sum mismatch, unavailable class/features, invalid subclass, failed prerequisite, unsupported combination, missing choice/equipment, separate pact slots, manual effect, and effect failure.

## Pack completeness and compatibility

`pilot`, `partial`, and `complete` remain unchanged. Pilot and partial packs show an incomplete-source label in the content workspace and always produce `PACK_INCOMPLETE` during preview. The identity guard still prevents a pilot identity from claiming complete coverage.

Schema version remains `2`. Existing effects retain their prior shapes and new fields use backwards-compatible defaults. No migration is needed because no stored field became required. Dexie records created before M1.4 may omit `equipmentBundles`; runtime and export treat that as an empty list.

## Remaining limitations

- Pact Magic slot quantities and refresh behavior are deliberately separate from combined multiclass slots.
- Known/prepared spell merging and per-class spellcasting ability selection need a spellcasting vertical slice.
- Currency alternatives are modeled but require a builder selection surface.
- Complex spell area/target/upcast idioms and richer monster action/recharge grammar remain outside this slice.
- Errata/reprint policy still needs a real controlled multi-edition pilot.
- The private Brammel mechanics still require independent rules review before being declared a canonical implementation.

## Gates

- Functional Brammel vertical slice: **GO after local pilot regeneration/validation**, provided it has no unexplained effect and all manual effects remain visibly review-required.
- Full PHB 2024 conversion: **NO-GO** pending the spellcasting, monster, errata, and independent-review gaps above.
- Multiclass character creation: **NO-GO for general release**; baseline prerequisites, progressions, proficiencies, subclass gates, and combined slots are covered, but pact and known/prepared-spell semantics still require vertical-slice validation.
